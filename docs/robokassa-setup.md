# Подключение оплаты через Робокассу

Платные услуги сайта «Любовь в цифрах» (VIP-статус и монеты) оплачиваются через Робокассу. Пароли магазина хранятся только на сервере (в функциях Netlify), браузер их не видит. Сумму к оплате тоже задаёт сервер.

## 1. Магазин в личном кабинете Робокассы

1. Войдите на https://login.robokassa.ru и создайте магазин для сайта.
2. Заполните данные об услугах. Для проверки магазина на сайте уже есть цены (раздел «Бесплатно и с VIP») и страница `oferta.html` с офертой, условиями оплаты и возврата и контактами.
3. В «Технических настройках» магазина укажите (вместо `ВАШ-ДОМЕН` подставьте адрес сайта на Netlify):

| Поле | Значение | Метод |
|---|---|---|
| Result URL | `https://ВАШ-ДОМЕН/api/robokassa-result` | POST |
| Success URL | `https://ВАШ-ДОМЕН/site/lyubov-v-cifrah/` | GET |
| Fail URL | `https://ВАШ-ДОМЕН/site/lyubov-v-cifrah/?pay=fail` | GET |
| Алгоритм расчёта хеша | MD5 (или другой, см. `ROBOKASSA_HASH`) | |

4. Скопируйте идентификатор магазина, пароль #1 и пароль #2. Для тестового режима в кабинете есть отдельная пара тестовых паролей.

## 2. Переменные окружения в Netlify

Netlify → сайт → Site configuration → Environment variables:

| Переменная | Что указать |
|---|---|
| `ROBOKASSA_LOGIN` | идентификатор магазина |
| `ROBOKASSA_PASS1` | пароль #1 (в тестовом режиме — тестовый пароль #1) |
| `ROBOKASSA_PASS2` | пароль #2 (в тестовом режиме — тестовый пароль #2) |
| `ROBOKASSA_TEST` | `1`, пока проверяете оплату; удалите после активации магазина |
| `ROBOKASSA_HASH` | алгоритм из настроек магазина: `md5`, `sha256`, `sha384` или `sha512` (по умолчанию `md5`) |
| `ROBOKASSA_RECEIPT` | `1`, если подключена фискализация (Робочеки) и в платёж нужно передавать чек |
| `ROBOKASSA_SNO` | система налогообложения для чека, например `usn_income` (только при `ROBOKASSA_RECEIPT=1`) |
| `ROBOKASSA_TAX` | ставка НДС для чека, по умолчанию `none` |

После изменения переменных запустите новый деплой (Deploys → Trigger deploy).

Пока переменные не заданы, сайт показывает «Оплата пока не подключена» и предлагает начислить покупку в демо-режиме.

## 3. Как проходит оплата

1. Человек нажимает «Оплатить» → сайт вызывает `POST /api/pay` с кодом товара.
2. Функция `netlify/functions/pay.mjs` берёт цену из каталога, формирует номер счёта и подпись `MerchantLogin:OutSum:InvId[:Receipt]:Пароль#1:Shp_product=…` и возвращает ссылку на `auth.robokassa.ru`.
3. После оплаты Робокасса:
   - отправляет уведомление на Result URL → `robokassa-result.mjs` проверяет подпись паролем #2 и отвечает `OK<номер счёта>`;
   - возвращает человека на Success URL → сайт отправляет параметры в `POST /api/pay-confirm`, функция проверяет подпись паролем #1, и сайт начисляет VIP или монеты.
4. Отказ от оплаты ведёт на Fail URL, сайт показывает, что деньги не списаны.

## 4. Цены

Цены заданы в двух местах, и они должны совпадать:

- `netlify/lib/robokassa.mjs` (`CATALOG`) — по этим ценам выставляется счёт;
- `site/lyubov-v-cifrah/index.html` (`SHOP`) — то, что видит покупатель;
- плюс таблица в `site/lyubov-v-cifrah/oferta.html`.

## 5. Демо-версия и свой сервер

На Netlify сайт работает в демо-режиме: купленный VIP и монеты записываются в браузер покупателя.

На своём сервере (`server/`, инструкция — `docs/deploy.md`, раздел 7) те же адреса `/api/pay`, `/api/pay-confirm` и `/api/robokassa-result` обслуживает сервер: заказ привязан к аккаунту, VIP и монеты начисляются в базе ровно один раз по уведомлению на Result URL. Переменные `ROBOKASSA_*` задаются в файле `.env` на сервере, а не в Netlify.
