# Как запустить сайт «Любовь в цифрах» на своём сервере

Эта инструкция — для человека без опыта программирования. Команды нужно копировать в окно терминала целиком, по одной.
Строки, начинающиеся с `#`, — пояснения, их вводить не нужно.

Что получится в итоге: арендованный сервер в России (VPS) с Ubuntu, на нём работает программа сайта (Node.js),
перед ней стоит веб-сервер nginx. Сначала сайт открывается по IP-адресу сервера (домена пока нет),
потом добавляется домен и защищённое соединение HTTPS.

> Важно: без HTTPS браузеры не дают сайту доступ к камере и микрофону (видеозвонки, голосовые, селфи для проверки)
> и не присылают push-уведомления. По IP-адресу можно проверить анкеты, переписку, оплату и модерацию,
> а для полноценной работы нужен домен с HTTPS (раздел 11).

---

## Быстрая установка одной командой

Если не хочется выполнять шаги 3–6 и 11–12 вручную: арендуйте сервер (шаг 1), подключитесь к нему (шаг 2) и вставьте одну строку:

```
curl -fsSL https://raw.githubusercontent.com/Serg1306/kot13061970-gmail.com/claude/keen-lamport-4oxlbx/deploy/install.sh | sudo bash
```

Скрипт сам установит программы, межсетевой экран, сайт, автозапуск, nginx и ночные резервные копии. Потом остаются три команды, каждая сама спросит нужные данные:

| Команда | Когда |
|---|---|
| `lyubov-domain` | купили домен и направили его на IP сервера — подключит HTTPS |
| `lyubov-mail` | чтобы коды входа приходили на почту (Яндекс, пароль приложения) |
| `lyubov-tkassa` | подключили интернет-эквайринг Т-Кассы — пароль терминала вводится на сервере и никуда не отправляется |

Обновить сайт до новой версии: `lyubov-update`. Ниже — то же самое по шагам, если хотите понимать каждую команду.

## 1. Арендуйте сервер

Подойдёт любой из российских провайдеров. Нужна виртуальная машина:

- система **Ubuntu 24.04** (или 22.04);
- 1–2 ядра, **2 ГБ памяти**, диск от 20 ГБ (фото пользователей занимают место — потом диск можно увеличить);
- публичный IPv4-адрес.

Где заказать:

- **Timeweb Cloud** (timeweb.cloud) → «Облачные серверы» → «Создать» → Ubuntu 24.04 → тариф на 2 ГБ → в разделе «SSH-ключи» можно оставить вход по паролю (пароль придёт на почту).
- **Selectel** (selectel.ru) → «Облачная платформа» → «Серверы» → «Создать сервер» → Ubuntu 24.04 → включите «Публичный IP».
- **Yandex Cloud** (cloud.yandex.ru) → Compute Cloud → «Создать ВМ» → Ubuntu 24.04 → включите «Публичный адрес: автоматически»; вход только по SSH-ключу (инструкция есть прямо в форме создания), имя пользователя задаёте сами.

Запишите **IP-адрес** сервера (например, `203.0.113.10`) и пароль или ключ для входа.

## 2. Подключитесь к серверу

- **Windows 10/11**: откройте «Терминал» или «PowerShell».
- **macOS**: программа «Терминал».

```
ssh root@203.0.113.10
```

(Вместо `203.0.113.10` — ваш IP. В Yandex Cloud вместо `root` — имя пользователя, которое вы задали; тогда перед командами ниже пишите `sudo`, или один раз выполните `sudo -i`.)
На вопрос «Are you sure you want to continue connecting» ответьте `yes`, затем введите пароль (символы при вводе не видны — так и задумано).

## 3. Установите нужные программы

```
apt update && apt upgrade -y
apt install -y curl git nginx sqlite3 ufw
# Node.js 22 из официального репозитория NodeSource
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
node --version
```

Последняя команда должна показать `v22.…` (22.5 или новее).

Включите защиту от лишних подключений (останутся только SSH и веб):

```
ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable
```

## 4. Скопируйте сайт на сервер

Создайте отдельного пользователя для сайта и папки:

```
useradd --system --create-home --home-dir /opt/lyubov --shell /usr/sbin/nologin lyubov
mkdir -p /var/lib/lyubov/data /var/backups/lyubov
chown -R lyubov:lyubov /var/lib/lyubov
```

**Вариант А — из GitHub.** Если репозиторий закрытый, создайте на GitHub токен (Settings → Developer settings → Personal access tokens → Fine-grained, доступ «Contents: Read-only» к этому репозиторию) и подставьте его вместо `ТОКЕН`:

```
git clone https://ТОКЕН@github.com/ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ.git /tmp/lyubov-src
cp -a /tmp/lyubov-src/. /opt/lyubov/
rm -rf /tmp/lyubov-src
chown -R lyubov:lyubov /opt/lyubov
```

**Вариант Б — со своего компьютера.** На своём компьютере (не на сервере!) в папке с проектом:

```
scp -r package.json server site netlify docs root@203.0.113.10:/opt/lyubov/
```

и потом на сервере: `chown -R lyubov:lyubov /opt/lyubov`.

В папке `/opt/lyubov` должны оказаться `package.json`, `server`, `site`, `netlify`.

## 5. Настройки: файл .env

Скопируйте пример и откройте его в простом редакторе:

```
cp /opt/lyubov/server/.env.example /opt/lyubov/.env
nano /opt/lyubov/.env
```

Пример заполненного файла (пока без домена, вместо `203.0.113.10` — ваш IP):

```
PORT=8080
HOST=127.0.0.1
DATA_DIR=/var/lib/lyubov/data
PUBLIC_URL=http://203.0.113.10
ADMIN_EMAILS=kot13061970@gmail.com

SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=robot@yandex.ru
SMTP_PASS=abcdefghijklmnop
SMTP_FROM=Любовь в цифрах <robot@yandex.ru>

DEV_CODES=0
AUTO_APPROVE=0

PUSH_ENABLED=0
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=mailto:kot13061970@gmail.com

CONSENT_VERSION=2026-10-14

METRIKA_ID=

TKASSA_TERMINAL=
TKASSA_PASSWORD=
TKASSA_RECEIPT=0
```

Что означает каждая строка:

| Переменная | Что указать |
|---|---|
| `PORT` | порт программы, оставьте `8080` |
| `HOST` | `127.0.0.1` — программа доступна только через nginx (так безопаснее) |
| `DATA_DIR` | где хранить базу, фото и ключи — `/var/lib/lyubov/data` |
| `PUBLIC_URL` | адрес сайта для ссылок в письмах: сейчас `http://IP`, после домена — `https://домен` |
| `ADMIN_EMAILS` | почты модераторов через запятую (раздел 9) |
| `SMTP_…` | почтовый ящик, с которого уходят коды входа и уведомления (раздел 8) |
| `DEV_CODES` | `1` — код входа показывается прямо на сайте без письма. Только для проверки, пока почта не настроена! На рабочем сайте — `0` |
| `AUTO_APPROVE` | `1` — фото появляются сразу, без модерации; `0` — после проверки в admin.html |
| `PUSH_ENABLED` | `0` — push-уведомления выключены (по умолчанию). `1` — включить, но только после уведомления Роскомнадзора (раздел 10) |
| `VAPID_…` | ключи push-уведомлений. Оставьте пустыми — сервер создаст их сам (раздел 10) |
| `CONSENT_VERSION` | редакция текстов согласий на обработку данных (дата, например `2026-10-14`). Записывается вместе с согласием каждого пользователя; меняйте, когда меняете тексты согласий |
| `METRIKA_ID` | номер счётчика Яндекс Метрики, если есть |
| `TKASSA_…` | данные терминала Т-Кассы (раздел 7 и `docs/tkassa-setup.md`) |

Сохранить в nano: `Ctrl+O`, затем `Enter`; выйти: `Ctrl+X`. Закройте файл от посторонних глаз:

```
chown lyubov:lyubov /opt/lyubov/.env
chmod 600 /opt/lyubov/.env
```

## 6. Автозапуск (systemd) и nginx

Создайте службу, которая запускает сайт при включении сервера и перезапускает его при сбое:

```
cat > /etc/systemd/system/lyubov.service <<'EOF'
[Unit]
Description=Любовь в цифрах
After=network.target

[Service]
User=lyubov
Group=lyubov
WorkingDirectory=/opt/lyubov
ExecStart=/usr/bin/node --no-warnings server/server.mjs
Restart=always
RestartSec=3
NoNewPrivileges=true
ProtectSystem=full
ReadWritePaths=/var/lib/lyubov

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now lyubov
systemctl status lyubov --no-pager
```

В выводе должно быть `active (running)` и строка «сервер запущен на порту 8080». Выйти из просмотра — клавиша `q`.

Настройте nginx — он принимает запросы из интернета и передаёт их программе:

```
cat > /etc/nginx/sites-available/lyubov <<'EOF'
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;

    # Фото и голосовые до 10 МБ
    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
EOF
rm -f /etc/nginx/sites-enabled/default
ln -sf /etc/nginx/sites-available/lyubov /etc/nginx/sites-enabled/lyubov
nginx -t && systemctl reload nginx
```

Откройте в браузере `http://203.0.113.10/` (ваш IP) — должен открыться сайт.
Проверка, что работает именно сервер, а не демо-режим: `http://203.0.113.10/api/config` показывает `{"live":true,…}`.

Журнал работы сайта (ошибки, а если почта не настроена — коды входа):

```
journalctl -u lyubov -f
```

(выход — `Ctrl+C`). Перезапуск после изменения `.env`: `systemctl restart lyubov`.

## 7. Оплата: Т-Касса

Когда Т-Банк одобрит заявку на интернет-эквайринг, в кабинете Т-Бизнеса появятся тестовый и боевой терминалы. Запустите на сервере `lyubov-tkassa` и введите **TerminalKey** и **пароль** терминала: сначала тестового (его имя заканчивается на `DEMO`), после проверки — боевого. Адреса уведомлений и возврата в кабинете указывать не нужно: сайт передаёт их Т-Кассе сам при каждом платеже, поэтому сначала подключите домен с HTTPS (раздел 11). Подробности — в `docs/tkassa-setup.md`.

Как это работает: сервер запоминает каждый заказ и чей он. Когда Т-Касса присылает уведомление об оплате (`/api/tkassa-notify`, подпись паролем терминала), VIP или монеты начисляются этому человеку ровно один раз, даже если уведомление пришло повторно.

**Сверка.** Если уведомление не дошло (например, сервер перезагружался), сервер раз в 10 минут сам спрашивает Т-Кассу о неоплаченных заказах за последние двое суток и начисляет найденные оплаты. Вручную: admin.html → «Платежи» → у заказа «не оплачен» кнопка «Проверить в Т-Кассе». Переменная `TKASSA_API_URL` нужна только для автотестов, в `.env` её не указывайте.

**Возврат денег** делается в два шага:

1. Сами деньги возвращаются в кабинете Т-Бизнеса: «Интернет-эквайринг» → «Операции» → найдите платёж по номеру заказа → «Возврат». Сайт не может вернуть деньги сам.
2. Затем в admin.html → «Платежи» у этого счёта нажмите «Оформить возврат» и напишите примечание (дата, причина). Кнопка только отменяет услугу на сайте: монеты списываются (баланс не уходит ниже нуля), срок VIP сокращается на купленные дни (но не раньше сегодняшнего момента), человек видит уведомление. В выгрузке CSV видны все возвраты.

Во вкладке «Платежи» есть поиск по почте, имени или номеру счёта, итоги за сегодня, месяц и всё время, сумма возвратов и кнопка «Скачать CSV» (открывается в Excel).

## 8. Почта для кодов входа

Нужен отдельный почтовый ящик, например на Яндексе или Mail.ru. Пароль от самого ящика **не подойдёт** — нужен «пароль приложения».

**Яндекс Почта:**

1. Войдите в ящик → id.yandex.ru → «Безопасность» → «Пароли приложений» → «Почта» → придумайте название → скопируйте пароль (16 букв).
2. В настройках почты (Все настройки → «Почтовые программы») включите «С сервера imap.yandex.ru по протоколу IMAP» и «Пароли приложений и OAuth-токены».
3. В `.env`:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=robot@yandex.ru
SMTP_PASS=пароль-приложения
SMTP_FROM=Любовь в цифрах <robot@yandex.ru>
```

**Mail.ru:**

1. Настройки ящика → «Безопасность» → «Пароли для внешних приложений» → «Добавить» → разрешите «Чтение и отправка почты» → скопируйте пароль.
2. В `.env`:

```
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_USER=robot@mail.ru
SMTP_PASS=пароль-для-внешних-приложений
SMTP_FROM=Любовь в цифрах <robot@mail.ru>
```

Адрес в `SMTP_FROM` должен совпадать с `SMTP_USER`, иначе почтовая служба не отправит письмо.
Порт 465 — защищённое соединение сразу (SMTPS); если провайдер почты даёт только 587, укажите `SMTP_PORT=587` (сервер включит шифрование командой STARTTLS).
После изменения — `systemctl restart lyubov` и попробуйте войти на сайт. Если письмо не пришло, загляните в журнал (`journalctl -u lyubov -n 50`) — там будет причина.

Пока почта не настроена, коды входа видны только в журнале сервера (строка «Код входа для …»).

## 9. Модераторы и страница admin.html

1. Впишите свою почту в `.env`: `ADMIN_EMAILS=kot13061970@gmail.com` (несколько — через запятую без пробелов).
2. `systemctl restart lyubov`.
3. Откройте `http://203.0.113.10/admin.html`, введите эту почту и код из письма.

Вкладки: «Фото на модерации» (одобрить/отклонить), «Подтверждение» (селфи с жестом рядом с главным фото анкеты), «Жалобы» (забанить/отклонить, список забаненных с кнопками «Разбанить» и «Удалить данные»), «Поддержка» (обращения пользователей и ответ от имени поддержки), «Платежи» (раздел 7), «Журнал уничтожения», «Статистика».

**Персональные данные — что делает сайт сам:**

- При первом заполнении анкеты человек ставит две отдельные галочки: согласие на обработку и согласие на распространение (анкету видят другие). Сервер записывает время каждого согласия, редакцию текста (`CONSENT_VERSION`) и IP-адрес.
- В настройках сайта человек может скачать все свои данные одним файлом (по 152-ФЗ, ст. 14) и удалить аккаунт.
- Каждое удаление данных записывается в **журнал уничтожения** (требование приказа Роскомнадзора № 179 от 28.10.2022): удаление аккаунта самим пользователем, удаление модератором, удаление селфи после проверки или через 30 дней. В журнале нет самих данных — только обезличенный номер, маска почты (`k***@gmail.com`), что удалено, основание, способ и кто удалил.
- Если удаляется забаненный, сайт запоминает только хэш его почты (не саму почту), чтобы он не зарегистрировался снова. Такие записи хранятся 3 года и потом удаляются автоматически.

**Что делать вам:**

- **Раз в месяц** откройте admin.html → «Журнал уничтожения», выберите период (с 1-го по последнее число прошлого месяца) → «Скачать CSV». Сохраните файл в папку с документами и храните 3 года. По требованию Роскомнадзора показываете эти файлы.
- **Если человек пишет на почту, что отзывает согласие** или просит удалить данные: «Журнал уничтожения» → внизу «Удалить пользователя по запросу» → его почта → основание «отзыв согласия» (или «запрос пользователя») → «Удалить». Ответьте ему, что данные удалены (по закону — в течение 10 рабочих дней).

## 10. Push-уведомления (выключены по умолчанию)

**Push выключен по умолчанию** (`PUSH_ENABLED=0`). Уведомления в браузер идут через серверы Google, Mozilla и Apple за границей — это трансграничная передача персональных данных, и до её начала нужно отдельное уведомление Роскомнадзора. **Включайте push только после уведомления Роскомнадзора о трансграничной передаче — см. `docs/legal/02-uvedomlenie-rkn.md`.**
Пока push выключен, сайт не предлагает подписаться на уведомления и не создаёт ключи; письма на почту работают как обычно.

Как включить:

1. Подайте уведомление (см. документ выше) и дождитесь, пока оператор появится в реестре с указанием трансграничной передачи.
2. В `.env`: `PUSH_ENABLED=1`, затем `systemctl restart lyubov`.
3. Ключи создавать не нужно: сервер сам создаст их и сохранит в `/var/lib/lyubov/data/vapid.json`. Этот файл входит в резервную копию (раздел 12) — если он потеряется, пользователям придётся заново разрешить уведомления. Если хотите задать ключи сами, впишите их в `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY`.

Push работает только по HTTPS (раздел 11).

## 11. Когда появится домен: адрес и HTTPS

1. Купите домен (например, у reg.ru, nic.ru или Timeweb).
2. В управлении DNS домена создайте **A-запись**: имя `@` → IP сервера. И ещё одну: имя `www` → тот же IP. Подождите от 15 минут до нескольких часов.
3. Проверьте: `http://ваш-домен/` открывает сайт.
4. Укажите домен в nginx (вместо `lyubov-v-cifrah.ru` — ваш):

```
sed -i 's/server_name _;/server_name lyubov-v-cifrah.ru www.lyubov-v-cifrah.ru;/' /etc/nginx/sites-available/lyubov
nginx -t && systemctl reload nginx
```

5. Получите бесплатный сертификат Let's Encrypt — он будет продлеваться автоматически:

```
apt install -y certbot python3-certbot-nginx
certbot --nginx -d lyubov-v-cifrah.ru -d www.lyubov-v-cifrah.ru --redirect -m kot13061970@gmail.com --agree-tos -n
```

6. В `.env` поменяйте `PUBLIC_URL=https://lyubov-v-cifrah.ru` и выполните `systemctl restart lyubov`.
7. В Робокассе замените адреса Result/Success/Fail URL на `https://ваш-домен/…` (раздел 7).

Проверка автопродления сертификата: `certbot renew --dry-run`.

## 12. Резервные копии

Всё ценное лежит в `/var/lib/lyubov/data`: база `lvc.sqlite`, папки `uploads` (фото, голосовые) и `private` (селфи на проверке), ключи `vapid.json` (если push включён) и секрет `secret.key` (нужен для журнала уничтожения и списка забаненных — без него они перестанут совпадать).
Базу нельзя просто копировать во время работы — используйте команду `.backup`, она делает целостную копию на ходу.

Создайте скрипт ежедневной копии (хранит 14 последних):

```
cat > /usr/local/bin/lyubov-backup <<'EOF'
#!/bin/sh
set -e
D=/var/lib/lyubov/data
B=/var/backups/lyubov
STAMP=$(date +%Y-%m-%d_%H%M)
sqlite3 "$D/lvc.sqlite" ".backup '$B/lvc-$STAMP.sqlite'"
tar -czf "$B/files-$STAMP.tar.gz" -C "$D" uploads private $(cd "$D" && ls vapid.json secret.key 2>/dev/null)
find "$B" -type f -mtime +14 -delete
EOF
chmod +x /usr/local/bin/lyubov-backup
/usr/local/bin/lyubov-backup && ls -lh /var/backups/lyubov
echo '30 3 * * * root /usr/local/bin/lyubov-backup' > /etc/cron.d/lyubov-backup
```

Копии на том же сервере не спасут, если пропадёт сам сервер. Раз в неделю скачивайте их к себе (команда на своём компьютере):

```
scp -r root@203.0.113.10:/var/backups/lyubov ./lyubov-backups
```

или включите у провайдера автоматические снимки диска (Timeweb: «Бэкапы», Selectel: «Снимки», Yandex Cloud: «Снимки дисков» / «Расписания снимков»).

**Восстановление** из копии:

```
systemctl stop lyubov
cp /var/backups/lyubov/lvc-ДАТА.sqlite /var/lib/lyubov/data/lvc.sqlite
rm -f /var/lib/lyubov/data/lvc.sqlite-wal /var/lib/lyubov/data/lvc.sqlite-shm
tar -xzf /var/backups/lyubov/files-ДАТА.tar.gz -C /var/lib/lyubov/data
chown -R lyubov:lyubov /var/lib/lyubov
systemctl start lyubov
```

## 13. Обновление сайта

Если копировали из GitHub (вариант А):

```
git clone https://ТОКЕН@github.com/ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ.git /tmp/lyubov-src
cp -a /tmp/lyubov-src/server /tmp/lyubov-src/site /tmp/lyubov-src/netlify /tmp/lyubov-src/package.json /opt/lyubov/
rm -rf /tmp/lyubov-src
chown -R lyubov:lyubov /opt/lyubov
systemctl restart lyubov
```

Со своего компьютера (вариант Б) — та же команда `scp`, что в разделе 4, затем `chown` и `systemctl restart lyubov`.
Файл `.env` и данные пользователей при обновлении не затрагиваются. Перед обновлением полезно сделать копию: `/usr/local/bin/lyubov-backup`.

## 14. Если что-то не работает

| Что видно | Что сделать |
|---|---|
| Сайт не открывается совсем | `systemctl status lyubov` и `systemctl status nginx`; в Yandex Cloud/Selectel проверьте, что у сервера есть публичный IP и в группе безопасности открыт порт 80 (и 443) |
| «502 Bad Gateway» | программа сайта не запущена: `journalctl -u lyubov -n 50` покажет ошибку (часто — опечатка в `.env`) |
| Письма с кодом не приходят | проверьте `SMTP_…`, пароль приложения, папку «Спам»; ошибка будет в журнале |
| Не загружаются фото («413») | в настройке nginx должна быть строка `client_max_body_size 10m;` |
| Нет камеры, микрофона, уведомлений | нужен HTTPS (раздел 11) |
| admin.html пишет «почта не входит в список модераторов» | проверьте `ADMIN_EMAILS` и перезапустите: `systemctl restart lyubov` |
| Оплата прошла, а VIP не начислен | проверьте TerminalKey и пароль (`lyubov-tkassa`) и что `PUBLIC_URL` в `.env` — ваш адрес с https; в журнале будут строки `tkassa: …` |

## 15. Звонки в мобильных сетях

Видеозвонки соединяются напрямую между браузерами (WebRTC) через общедоступные STUN-серверы. В некоторых мобильных и корпоративных сетях прямое соединение невозможно — тогда нужен свой TURN-сервер (программа coturn на том же VPS). Это можно добавить позже, когда появится домен: сайт уже умеет брать список серверов из поля `iceServers` ответа `/api/config`.
